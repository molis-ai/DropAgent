# 面板可挪；权限确认时置后

## 2026-09-11 实测问题修复

用户在 Review 应用中发现打开文件后窗口落到屏幕底部，拖动后收起再展开又回原处。本次保留黑白界面、内容随状态展开及现有权限处理，修复真实面板定位，完成等级为功能可用。

- 无已保存位置时，从菜单栏图标下方打开；所有内容变化都在当前屏幕可见区内布局。
- 手动拖动后保存左边和顶边，收起、再开及应用重启后继续使用；程序布局和动画不能覆盖它。
- 输入为菜单栏图标、屏幕可见范围、内容尺寸和已存位置；输出为面板实际 frame 与偏好文件。改动限于面板窗口/拖动/定位和对应诊断入口，不改文件处理规则。
- 当前证据：已有 `PanelPlacement` 坐标约束和 `panelX/panelTop` 存储；真实窗口使用默认 `NSHostingView` 尺寸约束，拖动使用 `performDrag`，旧测试未走 `AppDelegate`。先用真实窗口复现后裁定根因，不重写外围功能。
- 验收：首次显示位于菜单栏下；欢迎、打开文件和设置切换后实际窗口及内容可见；拖动后收起再开保持位置；重新读取偏好保持位置；无系统标题栏和调整大小入口。
- 验证：构建；新增 `--e2e --panel-only` 实际窗口回归；原 `--e2e --ui-only`；本地 Review 包检查与拖动试用。原权限授权流程不在本次重新授权。
- 假设：用户说的“工具栏”指 DropAgent 菜单栏图标；离屏位置按当前可见屏幕约束收回。

根因已复现：首次显示实际 frame 为 `(8, -1451, 1040, 2572)`，可见屏幕为 `(0, 0, 1800, 1129)`，内容期望高度仅 521。默认 hosting 尺寸约束覆盖手工窗口尺寸。AppKit 的 `performWindowDragWithEvent` 文档明确说明立即返回且可能不发送 mouseUp；原实现在返回时立刻结束拖动并保存，因此保存旧位置。

修复方案：实时面板关闭 hosting 自动尺寸约束，继续由内容测量和屏幕约束决定 frame。顶栏直接处理 AppKit 的 mouseDown/mouseDragged/mouseUp，用屏幕坐标维持鼠标与窗口的偏移，真正松手后保存一次；拖动期间不重算锚点，收起动画不写位置。不再依赖异步 `performDrag` 或鼠标状态轮询；实际自动化输入虽能命中顶栏，其全局 pressedMouseButtons 为 0，无法验证 Window Server 接管的拖动。直接处理事件与用户拖动走同一条可验证路径。

### 验证结果：通过

- 修复前的同一真实窗口检查失败（`/tmp/dropagent-panel-before.log`），修复后 `--e2e --panel-only` 通过（`/tmp/dropagent-panel-after.log`）。欢迎、PDF、设置的实际高度分别为 521、598、712，窗口与 hosting view 同尺寸、均在可见区内。移动期间调用布局不跳回、松手前不写偏好、松手后写入、收起再开和重读偏好均通过。
- 实际 Review 应用通过鼠标拖动验证：左边/顶边从 `(358, 843)` 移到 `(488, 723)`，收起重开后再向右拖 10 点得到 `(498, 723)`。随后用鼠标还原到 `(358, 843)`。重新选择用户原有 Markdown 文件，预览、操作区和整个面板完整可见；未修改文件内容。
- 最终 `--e2e --ui-only` 通过（`/tmp/dropagent-panel-ui-e2e.log`）；Review 构建打包通过（`/tmp/dropagent-panel-package.log`），签名完整性和 `git diff --check` 通过。

## 背景与目标

面板钉在菜单栏图标下，不能拖走。试用时系统权限确认弹窗会被这块面板挡住。

完成等级：功能可用。

## 当前行为

- 无边框，不可移动。每次打开按图标位置重算框。高度跟内容走。
- 点「授权」去开自动化时，面板仍在 statusBar 层。系统「允许控制某某 App」的确认框在它下面。
- 辅助功能那条会把面板藏掉再打开系统设置；这次不改那条。

## 范围

1. 按住顶栏空白处拖走。不上系统标题栏、红黄绿。不拉大小。
2. 记住位置（顶边和左边）。同一屏幕再打开用它，高度仍跟内容走；出界或换屏幕则夹回可见区。没拖过仍贴图标下沿。
3. 请求自动化权限（Safari / Chrome / Edge / Finder 等）时，面板沉到普通窗口层，确认框在前面。人点完允许或拒绝后，面板回到原来的层。

## 非目标

- 不拉大小。不吸附屏幕边。不多桌面各记一框。

## 方案

- 顶栏搜索和右侧按钮之间放拖动手柄，直接处理按下、移动和松手。松手时把顶边和左边写入偏好；程序性 `setFrame` 和收起动画不记。搜索框至少约 200pt，不被拖动手柄挤窄。
- 偏好里只存 `panelX`、`panelTop`。打开时用存下的顶边对齐，宽度高度仍按内容算。
- `StatusChrome.lowerForPermission()`：把 statusBar 层窗口降到 `.normal` 并挡住 activate 时自动抬回来；`requestAutomationOffMain` 前后各调用一次 restore。

## 验收

1. 拖顶栏，面板跟着走；松手后关再开，还在那里，高度仍跟内容。
2. 边角拉不动。仍无标题栏。
3. 点设置里的浏览器/Finder 授权，系统确认框不被面板挡住。
4. `swift build --product DropAgent` 与 `--e2e` 通过。
