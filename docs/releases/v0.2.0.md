**DropAgent v0.2.0 把面板换成文件工作台。** 相对 [v0.1.0](https://github.com/molis-ai/DropAgent/releases/tag/v0.1.0) 的上下文件卡，现在是左侧目录、右侧预览、底部常驻指令。原件仍然不动。

## 相对 v0.1.0 多了什么

这些来自 v0.1.0 之后的工作台改版，以及投放、侧栏、预览按钮、确认 / 整合 / 轮盘的打磨。

- **左目录、右预览。** 材料、生成结果、剪贴板是可折叠目录；点一行，右边看内容。指令始终在右下。窗口高度不再跟着确认、运行或对话乱跳。
- **整块面板都能投放。** 从 Finder 拖进打开的面板任意处，会出现「加入材料」，松手进副本。发给终端请拖到轮盘「发给终端」。已经接住的拖，Finder 不会回弹。
- **目录更好找、更好点。** 搜索在目录顶栏，可过滤架子上的文件，也可添加本机文件。文件相对目录缩进。悬停或选中后，行尾是复制、隐藏、删除；剪贴板另有「加入材料」，不再靠右键。
- **预览能对照、能改副本。** 结果可「对照原文」。可编文字右上角是带边框的「编辑副本」，不再是几乎看不见的图标。剪贴板点选只预览；复制或加入材料才有副作用。
- **整合要写出稿，不能交差。** 「整合」必须给出合成稿。Agent 回一句「已把三份材料整合成 brief.md」会当作失败，不会当成结果。结果重名会变成 `brief 2.md`。
- **复制的本地文件会进架子。** 在 Finder 里复制文件后，副本出现在材料里，原件不动。
- **闲时更让开。** 人离开后面板大约七成透明，并降到普通窗口层。点面板、拖文件进来或用快捷键会醒。

核心路径没变：放入材料 → 选择动作 → 确认范围 → 拿走新文件。图片 OCR 和 PDF 抽字仍在本机完成，不需要 Agent。

## 下载与安装

下载下方附件 **`DropAgent-v0.2.0-macos-arm64.zip`**，解压后将 `DropAgent.app` 拖进「应用程序」，双击打开，再点击菜单栏图标。

- **系统：** macOS 14 或更新版本。
- **芯片：** Apple Silicon（M 系列）；本次不提供 Intel 安装包。
- **无需开发工具：** 安装包不需要 Xcode 或 Swift。
- **签名状态：** adhoc 签名，尚未经过 Apple 公证。若系统拦截，确认来自本仓库后，按 [Apple 官方说明](https://support.apple.com/zh-cn/102445)，在尝试打开后前往「系统设置 → 隐私与安全性 → 仍要打开」。

`SHA256SUMS.txt` 可用于检查下载文件的完整性。

## 第一次试用

1. 点击 **「试用示例 PDF」**。
2. 选择 **「提取文字」**，确认后点击 **「开始提取」**。
3. 左侧结果组打开 `pdf.md`，复制内容或把结果文件拖到桌面。

这条路径不需要 Agent、辅助功能或屏幕录制权限。浏览器抓取、Finder 导入按需授权；拒绝相关权限仍可使用文件暂存和本机文字提取。

## 使用边界

- 扫描件 PDF 不等同于已完成 OCR；没有可选中文字时会说明无法直接提取。
- DropAgent 不自带模型，也不直接接云端模型 API。你选择的终端 Agent 仍可能使用它配置的云服务，并产生对应费用。
- 隔离能力由具体 CLI 决定。确认页会区分 Workspace Sandbox、Safe Copy 或未确认；Safe Copy 不代表整个宿主进程都处于严格沙箱内。内嵌终端对话会单独说明处理范围。
- 抓取登录墙、动态页面的正文可能不完整。网页抓取和真实 Agent 行为还受系统权限、网络及本机配置影响。
